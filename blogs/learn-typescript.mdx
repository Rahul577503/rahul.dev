TypeScript is a strongly typed superset of JavaScript that compiles down to plain JavaScript. The types only exist at compile time — they help your editor catch bugs, autocomplete code, and document intent, then disappear when the code runs in the browser or Node.

This cheatsheet is a quick reference for the syntax you'll reach for most often. Skim it, bookmark it, and copy from it.

## Install

- **Note:** You need to have npm installed.
- Avoid using TypeScript globally in a team to prevent version conflicts.

```bash
npm install -g typescript
```
## File Extensions

- TypeScript files have extensions `.ts` or `.tsx` (for React JSX files).

## Compile

To compile a single file to JavaScript:

```bash
tsc index.ts
```

To recompile automatically every time you save:

```bash
tsc --watch
```

## Run

To run TypeScript code:

```bash
node index.js
```

**Tip:** Use `nodemon` to watch for changes and restart the server automatically.

```bash
npm install -g nodemon
nodemon index.js
```

Or directly use `nodemon` with `.ts` files:

```bash
nodemon index.ts
```

## Config File

Use `tsconfig.json` to configure TypeScript. You can generate a config file with `tsc --init`.

```json
{
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src",
    "target": "es6",
    "module": "commonjs",
    "strict": true,
    "esModuleInterop": true,
    "sourceMap": true
  }
}
```

**Tip:** `"strict": true` turns on all the strict type-checking options at once (including `noImplicitAny` and `strictNullChecks`). Always enable it on new projects — it catches the bugs TypeScript exists to catch.

## Basic Types

```ts
let number: number = 32;
let string: string = 'John';
let boolean = true;
let any: any = 'this could be any type';

let arrayOfNumbers: number[] = [1, 2, 3];
let arrayOfStrings: string[] = ['a', 'b', 'c'];
let arrayOfAny: any[] = [1, 'a', true];
let arrayOfObjects: object[] = [{ a: 1 }, { b: 2 }];

let tuple: [string, number] = ['a', 1];
let tupleArray: [string, number][] = [
  ['a', 1],
  ['b', 2]
];
```

## Union

A union type (`|`) allows a value to be one of several types.

```ts
let union: string | number = 'a';
union = 1;
```

## Literal Types

You can use exact values as types. Combined with unions, this is great for modeling a fixed set of allowed options.

```ts
let direction: 'left' | 'right' | 'up' | 'down';
direction = 'left'; // ok
// direction = 'forward'; // Error: not assignable

type DiceRoll = 1 | 2 | 3 | 4 | 5 | 6;
let roll: DiceRoll = 4;
```

## Objects

```ts
type User = {
  name: string;
  age: number;
};

const user: User = {
  name: 'Jack',
  age: 32
};
```

## Functions

```ts
function add(a: number, b: number): number {
  return a + b;
}

const subtract = (a: number, b: number): number => a - b;

function log(message: string | number): void {
  console.log(message);
}
```

## Interfaces

```ts
interface UserInterface {
  readonly id: number;
  name: string;
  age?: number;
}

const user1: UserInterface = {
  id: 1,
  name: 'John'
};
user1.age = 47;
```

**`type` vs `interface`:** both can describe the shape of an object. Prefer `interface` for objects and classes you may want to extend or merge; reach for `type` when you need unions, tuples, or other shapes an interface can't express. In most day-to-day code they're interchangeable — pick one and stay consistent.

## Classes

```ts
class Person {
  constructor(public id: number, public name: string) {}

  register() {
    return `${this.name} is now registered`;
  }
}

const person1 = new Person(1, 'Jack');
```

## Type Assertion

```ts
let customerID: any = '123';
let customerIDAsNumber = customerID as number;
let customerIDAsNumber2 = <number>customerID;
```

## unknown, never & null

`unknown` is the type-safe counterpart of `any`: you can assign anything to it, but you must narrow it before you can use it. `never` represents a value that can never occur (e.g. a function that always throws). With `strictNullChecks` on, `null` and `undefined` must be handled explicitly.

```ts
let value: unknown = fetchData();
// value.toUpperCase(); // Error: must narrow first
if (typeof value === 'string') {
  value.toUpperCase(); // ok, value is now string
}

function fail(message: string): never {
  throw new Error(message);
}

let name: string | null = null;
name = 'John';
```

## Optional Chaining & Nullish Coalescing

`?.` short-circuits to `undefined` instead of throwing when a value is null/undefined. `??` provides a fallback only when the left side is `null` or `undefined` (unlike `||`, which also fires on `0`, `''`, and `false`).

```ts
const street = user?.address?.street;

const count = inputCount ?? 0; // 0 stays 0, only null/undefined falls back
```

## Type Narrowing

TypeScript narrows a union to a more specific type based on checks you write. This lets you safely branch on what a value actually is.

```ts
function format(value: string | number): string {
  if (typeof value === 'number') {
    return value.toFixed(2); // value is number here
  }
  return value.trim(); // value is string here
}
```

## Extending Classes (Subclasses)

```ts
class Employee extends Person {
  constructor(id: number, name: string, public position: string) {
    super(id, name);
  }

  register() {
    return `${this.name} is now registered as an employee`;
  }
}

const employee1 = new Employee(1, 'James', 'Developer');
```

## Generics

Generics let us write reusable components that work over many types instead of just one. `<T>` is a placeholder for a type that gets filled in when the function or class is used.

```ts
function getId<T>(id: T): T {
  return id;
}

const numberId = getId<number>(1);
const stringId = getId<string>('1');
```

## Enums

Enums let you give friendly names to a set of related constants. By default members are numbered from `0`, but you can assign string values for output that's easier to read and debug.

```ts
enum Color {
  Red,
  Green,
  Blue
}

let color: Color = Color.Blue; // 2

// String enums
enum Direction {
  Up = 'UP',
  Down = 'DOWN'
}

let move: Direction = Direction.Up; // 'UP'
```

## Pick and Omit

Pick and Omit are utility types in TypeScript:

```ts
interface User {
  id: number;
  name: string;
  lastName: string;
  age: number;
}

type Username = Pick<User, 'name' | 'lastName'>;

type UserWithoutId = Omit<User, 'id'>;
```

## More Utility Types

TypeScript ships several other built-in helpers that transform existing types so you don't have to redefine them by hand.

```ts
interface Todo {
  title: string;
  description: string;
  done: boolean;
}

// All fields optional
type PartialTodo = Partial<Todo>;

// All fields required
type RequiredTodo = Required<Todo>;

// All fields read-only
type ReadonlyTodo = Readonly<Todo>;

// A map from keys to a value type
type TodosById = Record<string, Todo>;
```

## Typing async / Promises

An async function always returns a `Promise<T>`, where `T` is the resolved value type.

```ts
async function getUser(id: number): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}
```

## Wrapping Up

That's the core of day-to-day TypeScript. The fastest way to get comfortable is to turn on `strict` mode, let the compiler complain, and follow its suggestions. When in doubt, the [official handbook](https://www.typescriptlang.org/docs/handbook/intro.html) and the [TypeScript Playground](https://www.typescriptlang.org/play) are excellent places to experiment.
